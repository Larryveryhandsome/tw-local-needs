# tw-local-needs｜在地需求雷達（地方生活需求媒合雛形）

地方上的生活需求（搬家、修繕、團訂、長輩接送……）常常散落在社群貼文、電話和熟人之間，**有需要的人不知道問誰，有能力的人也接不到案**。
這個專案是一個「需求提交 → 確認整理 → 媒合服務者 → 追蹤結果」的網頁雛形，改一個設定檔就能變成你的城市、鄉鎮或社區版本。

- **公開頁**：居民提交需求；確認過的需求才公開**去識別化摘要**，聯絡方式不會出現在公開頁。
- **營運後台**：改狀態、指派服務者（自動只列出類別、地區相符的人）、**標出可能重複的需求**、聯絡方式預設遮罩。
- 沒選類別時**依說明文字自動分類**；成果統計；**匯出 CSV**（Excel 不亂碼、防公式注入）；JSON 備份與還原。
- 免安裝、免伺服器：純網頁，雙擊就能用，也可以放 GitHub Pages。

**線上示範（虛構資料）：** https://larryveryhandsome.github.io/tw-local-needs/

> ⚠️ **這是單機示範版**：資料存在瀏覽器的 localStorage，**只有那台電腦的那個瀏覽器看得到，後台也沒有登入保護**。
> 適合做提案展示、社區試辦、驗證需求；正式收真實民眾資料前，請接上資料庫與帳號權限（見下方「要正式上線的話」）。

## 適合誰

- 地方創生團隊、社區發展協會、青年返鄉團隊：想**驗證地方需求**、做計畫提案展示
- 里辦公室、社福團體：整理居民的生活需求、轉介在地服務
- 想做媒合平台的開發者：可以當前端雛形與資料結構的起點

## 怎麼用

1. 下載這個專案（綠色 **Code** 按鈕 → **Download ZIP**），解壓縮。
2. 用記事本打開 **`config.js`**，改：
   - `name`、`region`：平台名稱、地區（例如「某某鎮需求雷達」「某某鎮」）
   - `areas`：表單的地區選項（里、村、行政區…）
   - `categories`：需求類別與自動分類用的關鍵字
   - `NEEDS_SAMPLE`：示範資料，可以清空或改成你的
3. 雙擊 **`index.html`**（公開頁），**`admin.html`**（營運後台）。
4. 要放到網路上給大家看：把整個資料夾放到 GitHub Pages 或任何靜態網站空間即可。

### 後台怎麼操作

| 動作 | 說明 |
|---|---|
| 改狀態 | 待確認 → 已確認（才會出現在公開頁）→ 媒合中 → 已完成／已取消 |
| 指派服務者 | 下拉選單只列出類別相同、服務範圍包含該地區（或寫「全市」）的服務者；指派後自動改成「媒合中」 |
| 可能重複 | 同地區、同類別、標題很像、尚未完成的需求會標出來 |
| 看聯絡方式 | 預設遮罩，點一下才顯示 |
| 匯出 CSV／下載備份 | 定期備份！清除瀏覽器資料會不見 |

## 要正式上線的話（建議清單）

原則上收真實個資前，至少要做到：

1. **資料庫與帳號**：把 `js/needs.js` 的資料存取改接後端（例如 Firebase、Supabase 或自己的 API），後台要登入、分權限。
2. **個資告知**：依《個人資料保護法》告知蒐集目的、保存期限、聯絡窗口，並提供刪除管道。
3. **審核與防濫用**：驗證碼或限流、敏感內容過濾。
4. **備份與紀錄**：定期備份、保留誰改了什麼的操作紀錄。
5. **免責與轉介說明**：平台不是政府機關，媒合不等於背書。
